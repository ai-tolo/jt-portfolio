Tolo.Cloud

a creative archive that doesn't try to be creative for you

00 · Thesis

Utility, not synthesis.

The computer sorts, fingerprints, surfaces, and removes format friction.
The artist still chooses, still drags, still arranges.

Tolo.Cloud catalogs every audio + video file across iCloud, T7, and the Photos library, surfaces what's interesting via objective signals, and writes promotion-ready loops directly into Ableton Live's own browser. It does not auto-write Substack posts, propose albums, or push prompts. It will not. By design.

01 · Architecture

Four layers, one catalog, many surfaces.

The M1 (2020 MacBook Pro) holds the catalog and runs the engine. M3 is the daily driver and the dev surface. They talk over Tailscale. Everything else fans out from there.

Capture sources flow down. Inboxes split system writes from curator saves. Surfaces are interchangeable clients on the same engine verbs.

What lives where

M1 brain — FastAPI :8765 as com.jont.console-api. inventory.db WAL-mode SQLite. Waveforms in ~/automation/data/waveforms/, extracted audio in ~/automation/data/extracted-audio/, mix variants in ~/automation/data/engineer_variants/.

M3 surface — Astro at uxjon.com, Vercel-hosted. Auth-gated /portal proxies the M1 over Tailscale Funnel. Static public site at / and /sounds.

iCloud as the cross-machine wire — ~/Library/Mobile Documents/com~apple~CloudDocs/ is the only path that rewrites cleanly between users jontollefson (M1) and tolo (M3). T7 SSD reachable wherever it's plugged in.

02 · The pivot

The wall that bent the build.

Build 3 was supposed to be a Max-for-Live device inside Ableton: select a row, drag it onto a clip slot, watch it warp. The device was code-complete in ~/console-build/device/ when two architectural walls killed the direction.

The right move was not to push harder against the platform. It was to ask which existing affordance does the job already, and write into that.

The reframe in one sentence

Stop building a synthetic surface inside the DAW. Use the DAW's existing one.

The promotion pipeline (.wav-only, Phase 1)

  1. Copy source WAV to ~/.../_Soundbending/loops/{bpm}_{key}_{stem}.wav. Null BPM/key fall back to unknown_bpm / unknown_key.
  2. Normalize loudness to -14 LUFS via single-pass ffmpeg loudnorm=I=-14:TP=-1.5:LRA=11.
  3. Update assets.live_loop_path to the absolute path. Portal flips the button to ✓ IN LIVE.

First three test loops landed end-to-end on 2026-05-17: rowid 16240 (KIT_01 top-loop, 120 A#), 12518 (an unknown-BPM SoundCloud cloud demo), 13574 (55_Cmaj_0_what_you_know.wav).

03 · The surface

The card grew up.

The BucketCard went through twelve visible rounds of design between 2026-05-18 and 2026-05-21. Each round was a subtraction or a reframe. The brand emerged through restraint, not addition.

Cassette-spine, then pink-orange buttons, then title-led neon green. The medicine-container pill replaced rows of letter tiles. The selected-card gradient reveals on the title chip alone.

Design conventions that survived

Title in italic mono 17px, neon green #00ff4d, on a green-wash chip with a 32%-alpha border. The filename is the identity.

BPM/key as a borderless italic mono subtitle. The number + key letter in cyan #0ec4fc; the unit + mode in muted cream.

LCD duration in pink with a soft halo, left of the waveform. The waveform itself doubles as the play surface.

J/L/F/T pill as a vertical medicine container with shared horizontal dividers. Active tile lights up in pink-red. The dividers above and below the active tile pick up matching wash.

What got cut

Star-rating buttons. ⚡ Kudos boosts. The ⚡ ticker. Per-tile borders on the pill. The dedicated ▶ button. The X keyboard shortcut. The +Queue button. The keyboard-shortcut help panel. The sub-tab strip. The Surprise tab. The Library tab.

The rename

"The Console" → "Tolo.Cloud" on 2026-05-19. The trigger word on the public home page changed from console to cloud the next day. The design had found itself; the wordmark caught up.

04 · The contract

Verbs are the contract.

The whole system is a FastAPI process. Each endpoint is a verb. The Portal is one client of those verbs. An iPad surface could be another. A future webview could be a third. The catalog is the source of truth, and the verbs are how anyone reads from it or writes into it.

When Surprise and Library got deleted on 2026-05-17, the catalog didn't change. Three surfaces collapsed into one. That's what verbs-as-contract buys.

Quoted, verbatim, from the session that triggered the 3-tab consolidation

"i think at this point it'd make sense to consolidate the console's ui. library doesn't make sense anymore as a separate page, the bucket's page is really the library now... 'surprise' page also feels like bloat now."

05 · The mix engineer that emerged

Build 5 · Engineer.

Once the catalog could promote loops into Live, the next question was: can the system also help me finish the work, not by writing it, but by giving me a fast taste-feedback loop on mixing decisions? Build 5 is that: a per-track mix agent that renders six variants across three taste axes and presents them as A/B pairs. Audio tinder.

Source stems → librosa analyzer with section detection → Claude planner reasoning per stem per section → pedalboard renderer with crossfaded section chains → 5-target translator. The UI is one pair card: A on the left, B on the right, free-text comment, pick.

What the agent respects

The planner is told that the source defines focal element, masking conflicts, and stem relationships. Processing-for-the-sake-of-processing is the failure mode. The agent doesn't get to add reverb to clean vocals because it likes reverb. It has to motivate every move from the analyzer's reading of this mix.

Cross-axis memory

Free-text comments on any pair persist into mix_judgements. The next render on the same source reads the full comment history into the planner's prompt context. A space-axis retry mentioning "kick is buried" will also address vocal feedback from a prior focal-axis pair on the same track. Verified in production on 2026-05-21.

Translation badges

After every render, five Pedalboard chains simulate phone, AirPods, laptop, car, and club playback. Per-band energy deltas + stereo collapse for mono targets get translated to plain-language flags: phone: vocal disappears club: translates clean.

Phase 5, in design

A reference catalog of artists I love (Tame Impala, Frank Ocean, 070 Shake, Travis Scott, Bon Iver, etc.) with per-track notes. The planner pulls "closest references for this source" as taste anchors. v1: text-anchor only. v2: audio-derived feature similarity.

06 · The boundary

What it deliberately does not do.

The "won't do" list is short on purpose. It's checked before any feature lands. Every entry is a place where the machine would pretend to author. Every one is a feature an adjacent product ships. The cost of including any of them is the same: I'd stop trusting that the surface is mine.

  • Write Substack, LinkedIn, or Instagram posts without an explicit draft invocation.
  • Propose albums, EPs, or song concepts.
  • Push daily prompts at me.
  • Listen to voice commands during a session.
  • Touch the desktop.
  • Publish to streaming platforms.
  • Make creative decisions on my behalf.
  • Vibe-match without measurable features.

08 · Where this points

The point is more music made.

uxjon.com/sounds already exists as a public route. Items flip to public via a toggle on any card. The path from "this loop is interesting" to "this track is out" runs through the same database and the same verbs. No second pipeline. No second deploy.

The 99.7% waveform coverage matters because every triage decision is informed by a real signal. The Buckets-to-Live promotion matters because it removed the step that used to live between "this fragment is good" and "this fragment is in a Live project." The density gate matters because it stopped lying about which transcripts were worth reading.

3,750 rows still sit in the inbox bucket. 215 promotable loops are queued. The machine just made choosing cheaper.
