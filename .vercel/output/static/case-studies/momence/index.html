Case Study 02

Momence

A customer profile that bends to fit each business.

Role
Sole designer, self-initiated case study
Timeline
May 2023 (48-hour take-home)
Tools
Figma
Tags
B2B SaaS · Design Systems · Component Library · Web · Mobile

Context

Momence is a B2B SaaS platform serving fitness studios, yoga instructors, and other small businesses managing customer relationships, scheduling, and payments. This was a final-stage take-home for their senior product designer interview: two days, one screenshot of the existing customer profile, and a written brief for a yoga-studio admin managing customers with active memberships, packs, and sessions.

The existing UI was dense but flat. Identity data, financial metrics, behavioral history, and configuration all shared the same visual weight on one undifferentiated surface.

The Problem

Reading the existing UI surfaced three structural issues:

  • Flat hierarchy. Identity, finance, behavior, and admin configuration shared the same visual weight. Nothing said "look here first."
  • No tenant flexibility. A yoga studio doesn't surface the same priorities as a B2B coaching practice, but the layout couldn't be tailored.
  • Mobile parity gap. A dense desktop layout with no mobile-considered counterpart, despite an audience often running their business from a phone between classes.

The Approach

I decomposed the existing UI into four functional categories:

  • Client contact. Identity, communication.
  • Business-specific. Financial metrics, subscriptions, credits.
  • Flex fields. Per-tenant custom configuration.
  • User interactions. Activity feed, message history.

Categorization first, layout second. The component schema became the foundation for the redesign, with primitives sized so an engineer could implement them without re-deriving the structure.

The Solution

Web (1366px). A customer detail page built on draggable modules sitting on top of the four-category schema.

Primary KPIs lead (sessions, total spend) with trend indicators (+11% over 3 months, +17% last month) so a number reads as direction, not just a snapshot.

The Recent Activity feed unifies messages, payments, class check-ins, and email threads behind one set of macro icons. A right rail surfaces upcoming events, documents, automations, and tickets, each collapsible.

Mobile (360px). Collapsible flex menus preserve density without losing usability. A calendar surface and status indicators lead, putting time-sensitive context first for someone running a studio between back-to-back classes.

Design Principles

  • Schema before layout. Categorization is the contract; layout is the implementation.
  • Modularity. Every block is swappable, not hard-coded.
  • Density without noise. KPIs lead, supporting context follows.
  • Trend over snapshot. Financial metrics show direction, not just current state.

Reflections

Decompose before you draw. Breaking the existing UI into four functional categories before any layout work is the move I'd repeat on any data-dense admin redesign. Without it, "drag to rearrange" becomes drag-to-rearrange chaos. With it, modularity becomes a customer-tailoring feature instead of a usability tax.

A snapshot is data. A snapshot with direction is product. Trend indicators on KPI cards move users from "read the number" to "act on the movement." That's where data-dense admin tools earn their keep.

Notes

Final-stage take-home for Momence's senior product designer interview, May 2023. 48 hours from brief to submission, working from one screenshot of the existing customer profile and a written spec for a yoga-studio admin user. Not shipped. All design decisions are mine.
